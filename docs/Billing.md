# Billing

## Production Billing Standard

[Production-Billing-Standard.md](Production-Billing-Standard.md) defines the approved V1 subscription and prepaid individual PAYG catalogs, ownership boundaries, customer meters, provider-charge separation, and hardcoded-value disposition. Customer charges stay disabled until ISSUE-248 records a go decision.

The owner revised this decision on 2026-09-27: use the production instance and a live account for verification. Provider answers, separate staging, two trial tenants, and three approval owners are not customer billing prerequisites. The existing platform-admin API records an owner enable/stop decision with fresh MFA. New usage only is eligible; historical shadow usage is not promoted. Supplier evidence remains a separate report and retains missing or mismatched results. This policy supersedes older release-gate wording below.

## Durable Billing Foundation

Migration `0016_panoramic_hobgoblin.sql` adds the production billing tables. Immutable catalog, ledger, adjustment, and PAYG credit rows have database triggers that reject updates and deletes. Tenant-owned records use tenant-qualified keys and idempotency constraints. Customer charges and supplier costs use separate integer minor-unit fields.

`billing_tenant_states` is a public read-model cache. It is not the financial ledger. New tenant state starts with no plan, subscription, usage, balance, invoice, entitlement, or checkout. Test fixtures must create the billing state that each test needs.

## Usage Metering

The configured AssemblyAI provider now writes a connection and unresolved request before opening its socket. Browser sandbox and standard PSTN calls use this recorder. Valid `Termination` events save the native `audio_duration_seconds` and `session_duration_seconds` values with the server-owned tenant, session, connection, and provider session IDs. Standard PSTN records also contain the trusted call session ID. Session duration is not replaced by audio duration or Zara runtime duration. No audio, transcript, or API key is saved in these records. This uses migrations 0037 through 0039; apply them before deploying the configured provider.

On stop, the provider sends `Terminate` once, stops accepting audio and new turns, and waits up to five seconds for the provider response. A stop before socket open is sent when it opens. Missing or invalid usage stays unresolved. A failed start write prevents the connection; a failed final write does not produce a successful usage record. This is a bounded socket-drain policy, not voice turn detection. No recovery source for events lost with the process has been added.

This capture is locally verified for sandbox streaming, one-turn transcription, and the standard PSTN execution boundary. The authorized Twilio socket now connects standard calls to AssemblyAI, the shared text-model router, and Cartesia. Provider audio remains native 8 kHz mu-law. Stop waits for STT usage persistence and in-flight tool work before durable call finalization. This does not qualify live provider behavior, supplier costs, complete cycle coverage, or provider accounting time. The stored time is Zara's request-start time, not a provider billing timestamp. AssemblyAI release evidence remains unavailable until the remaining coverage and cost checks pass.

OpenAI chat requests now have durable supplier records in `provider_usage_requests` (migration 0037). The configured router writes a request before calling OpenAI and saves valid native token counts once. Missing usage or a failed request stays unresolved. Records include tenant and available session identity, but no conversation text or secret. The shared command reads these records when `DATABASE_URL` is explicitly set. Without it, observation data remains absent. Use the intended database; the command does not load `.env` automatically.

`OPENAI_PROJECT_ID` is an optional non-secret project ID for the runtime process. When set, the same value is sent through OpenAI's project header and stored on the request. When absent, records retain a null scope and cannot be assigned to a shared project comparison. This setting requires no new provider token. Run migration 0037 before deploying the configured recorder; database write failures must not permit unrecorded provider requests.

The live premium OpenAI transport also records `response.created` and `response.done`. Each response has a stable provider/project identity and the server-owned tenant and premium session ID. Valid completed, cancelled, failed, and incomplete responses retain native input/output totals and optional text/audio/image/cache counters. Cached tokens remain a subset of input tokens. Replay preserves the first Zara receipt time because these events do not supply a provider response timestamp. A changed result or tenant/session identity is rejected. Simulator events are excluded.

Realtime writes start independently for separate source IDs. Events for one source ID retain their order and first receipt time. At most 128 events can be pending. Only selected usage fields are retained; audio and transcript payloads are excluded. If the first event includes final usage, its initial insert also saves that usage. Exact replay is safe; changed facts are rejected.

Audio delivery does not wait for the database. A write error or capacity overflow stops further provider sends and closes the connection with a fixed safe reason. Known transient database errors get one retry of the retained event. The connection remains unresolved after a recording error, even if that retry succeeds. Usage received before the physical socket closes can still be saved; terminal connections no longer forward it to runtime consumers. Finalization waits for pending writes. These are bounded in-process retries, not a durable queue: process failure can still lose observations not yet committed. No provider recovery API is assumed.

Migration `0038_provider_usage_connections.sql` adds separate connection records. The live OpenAI transport saves a start record before it opens the provider socket. A failed start write prevents that connection. Every connection attempt has a new ID, including reconnects. Setup failures and socket termination can write one final outcome and the observed provider session ID. A clean final record waits for queued usage writes; recording errors leave the start unresolved. No provider error text is saved.

Shared reports include `connectionCoverage`. Its records include connections that overlap the period and older unresolved starts. An unresolved start is not proof of a crash: the connection can still be active, or its final write can have failed. The reader keeps `complete: false`. A clean socket close does not prove complete provider usage, and no lost usage is reconstructed. Run migration 0038 before deploying this transport or using the database-backed report command.

The same private report now includes `usageReview`. It lists unresolved requests and unresolved or failed connections with their stored tenant/session/connection/call identity. Quantities remain null. The required action is to obtain original provider evidence, not to estimate usage or assign shared totals to a tenant. Missing database evidence produces an unavailable list, not an empty success. This is a report from durable rows, not a background recovery worker. Coverage remains incomplete even when the list is empty.

Migration `0039_provider_usage_attribution.sql` links live OpenAI Realtime usage to its connection. PSTN call start uses the call ID from the verified dispatch snapshot. Agent transfers retain that call ID on the replacement connection. The recorder keeps the connection ID for both response and transcription records. Reconnects get separate connection IDs but retain the supplied call identity. Browser connections have no PSTN call ID. User IDs and provider message bodies do not supply this identity.

The repository and database reject links with a different tenant, premium session, provider, or project. Transcription can use a different model on the same connection. Exact replay keeps the original connection; changed links are rejected. Historical null links remain null. Tenant reads and platform reports include stored links, but reports still mark coverage incomplete. Rollback refuses to remove any stored link. Run migration 0039 before deploying the recorder or using the database-backed report command. This local change does not qualify live usage or enable charges.

The same live transport now records separate input-transcription completion and failure events. A transcription record uses the model from the actual session configuration. Its key includes the provider session ID from `session.created`, item ID, and content index. This keeps reused item IDs in separate provider sessions distinct. Exact replay keeps the first receipt time; changed usage or tenant/session/model identity is rejected. Missing source identity or model is not invented.

Completed transcription records have `sourceKind: realtime_transcription`. Their `transcription.usage` field retains the provider's token or duration variant. Fractional seconds are not rounded or converted to tokens. The generic totals map contains only `transcriptionRequestCount`; transcription tokens are not added to voice-response or chat totals. The record excludes transcript text, log probabilities, and provider error text. Failed or invalid usage stays unresolved. The existing shared completion reader excludes completed transcription records and still reports incomplete coverage. The shared command now collects the independent OpenAI audio-transcription report. It compares native seconds and request counts by model and full UTC-day bucket. Token-only events have unknown comparison seconds; no token-to-second conversion is applied.

This is partial capture, not release qualification. Transcription timestamp qualification, token-only unit matching, other endpoints/shared-key activity, Cartesia credits, supplier costs, crash recovery, UTC boundary qualification, and complete recording coverage remain pending. The reader therefore keeps `complete: false`. No historic customer duration or zero value fills these gaps. The database prevents final-record changes/deletion; rollback refuses to drop a nonempty table.

Shared Cartesia keys and OpenAI projects belong to the platform, not to one tenant. `npm run billing:collect-shared -- <UTC-start> <UTC-end> <Cartesia-key-ID> <OpenAI-project-ID> <new-output-file>` collects their provider-native reports with the existing `CARTESIA_ADMIN_API_KEY` and `OPENAI_ADMIN_KEY` environment variables. Use complete UTC days and an existing private output directory. Do not put tokens in arguments or commit the output. The command does not load an environment file automatically.

The output has a separate `transcription` entry with the provider report, durable observations, and comparison. Provider facts come from `/v1/organization/usage/audio_transcriptions`, grouped by project and model. Decimal seconds are added exactly. Missing coverage, unresolved requests, unsupported units, duplicate facts, and invalid scope or period prevent a match. Missing observations remain unknown. The reader counts unresolved OpenAI requests conservatively because their endpoint is not yet known. The report uses first receipt time for stored Realtime events; this has not been qualified against provider bucket timing.

Both completion and transcription snapshots include `unresolvedRequestCount`. The count includes unresolved requests before the report end, including requests from earlier periods. Missing results have no known end time or endpoint, so they do not expire at midnight or become zero usage. These are potential coverage gaps, not usage assigned to the current period. The count excludes other providers/projects and requests starting at or after the report end. The shared comparison reports `observation_unresolved` even when coverage is already incomplete. A nonzero or missing count cannot produce a match.

Local checks confirm start-inclusive, end-exclusive UTC selection and exact replay after a failed final write. Replay requires the original provider event and retains its first receipt time, connection, and tenant. The test supplies that retained event; production has no durable source that can replay events lost with a process. A successful replay does not close an unresolved connection or prove complete coverage. Provider accounting-time alignment is still unqualified. Do not substitute the replay time, call duration, or a shared report total for missing native usage.

These local reports have `scope: platform` and `status: awaiting_usage_comparison`. The command refuses to overwrite a file. It does not create database release evidence, alter billing state, or certify a tenant bill. Each report includes a comparison result. Until the runtime persists complete native observations, this result is `incomplete` with `observation_coverage_missing`; the collector does not replace missing counts with zero. Do not map a shared key or project exclusively to Tuzzy or ZARA AI.

The shared comparison function checks provider scope, period, source identity, duplicate facts, and complete observation coverage. It compares Cartesia credits and OpenAI token/request totals directly. OpenAI costs use integer micro-units separated by currency; values that cannot be represented exactly at this precision fail validation. It includes every observation in the shared scope, including test and non-billable use. Its input must come from trusted server records, not customer meter values or a tenant upload. OpenAI chat and premium Realtime response capture and the partial production reader are implemented; complete native coverage remains pending.

Tenant provider-report validation is not an independent usage comparison. A well-formed Cartesia, OpenAI, or Gemini report retains its native totals but returns `provider_observation_comparison_missing` until a qualified same-unit comparison exists. It cannot qualify charge release from report shape alone. Structural errors retain their specific reasons. Polar meter quantities, prepaid balances, and invoice amounts must be numeric nonnegative safe integers; nulls, text, booleans, and arrays must not become zero or positive evidence.

Daily tenant reconciliation now also checks PSTN execution sessions against runtime ledger rows. Both database reads are tenant-scoped. The check compares each completed call's connected duration, meter, unit, and session identity, not only the total. Missing or duplicate ledger facts, orphan ledger facts, and mismatched quantities create a critical `tenant_session_ledger_mismatch`. Empty periods and missing successful-call connection times remain incomplete. Failed or expired calls that never connected have zero runtime. Browser sandbox ledger rows are excluded from this PSTN-only audit; this does not qualify browser usage or provider cost allocation.

Only trusted server lifecycle events can create billing ledger facts. Tenant request bodies cannot submit a price, charge amount, usage fact, or PAYG debit. The legacy tenant mutation routes for generic usage, telephony minutes, and runtime costs return `404` in the production module graph.

The trusted producer resolves the price catalog that was effective at the event time. It writes stable tenant-qualified idempotency keys, raw runtime seconds, customer charge data, and supplier cost data to the Postgres ledger. Standard and premium runtime are separate meter classes. Subscription and PAYG settlement use the same trusted facts. All charge delivery remains `shadow` until ISSUE-248 records a release decision.

Complete subscription shadow facts use one transaction for the ledger insert and its durable Polar outbox row. Stable external event IDs make retries idempotent. The bounded worker preserves failed delivery for retry and does not delete the authoritative ledger fact. PAYG does not send standard or premium usage meters directly; it requires one later `payg_charge_minor` session debit.

Subscription finalization applies included runtime first, then prepaid credit, then invoice overage. Each settled runtime and carrier row retains raw duration. Its `customerAmountMinor` is the invoice remainder; metadata retains `grossCustomerAmountMinor`, `includedRuntimeSeconds`, and `settlementMeterKey: subscription_charge_minor`. The outbox sends the remainder in USD cents, including zero, not the raw duration. Prepaid credit is applied to runtime first, then carrier charges. Its separate `payg_charge_minor` event commits with the debit and has no invoice price. A $1 charge after included allowance, with $0.40 prepaid, therefore sends 40 credits-only units and 60 invoice units. Retries retain the same event IDs.

Recovery requires the finalized reservation's included seconds before it can publish subscription usage. Missing catalog, rates, carrier duration, or invalid settlement amounts retain the durable recovery job for retry or dead-letter review; no partial settlement is published. Historical facts are not rewritten. Old calls without a full settlement remain subject to their existing delivery rules. Supplier comparisons retain full carrier amounts and raw runtime. Configure the new meter before enabling delivery; see the [release runbook](Runbooks/billing-charge-release-gate.md).

The worker uses processing leases, exponential retry, dead-letter state, and tenant-scoped audited replay. A crashed processing lease can return to pending state. A lifecycle scheduler checks due rows every 30 seconds, prevents overlapping passes, and waits for the active pass during shutdown. Delivery is disabled by default. Enable and delivery checks reject missing production credentials, sandbox mode, a missing webhook secret, or incomplete catalog mappings. These checks do not block API startup or the owner stop action.

One PAYG session debit and its credits-only outbox event commit in one database transaction. The event uses the `payg_charge_minor` meter, a stable external ID, and the related Zara session ID. It does not send standard runtime, premium runtime, or telephony meters as a second customer charge.

Tenant-cycle reconciliation reports missing, duplicate, late, and quantity-mismatched Polar usage. PAYG reconciliation compares the durable $5 grant and session debits with the Polar meter balance. Dead-letter delivery and late usage emit fixed low-cardinality metric counters and alert signals. Metric labels do not include tenant or event IDs. These reports and alerts do not enable charge delivery.

Polar payment-state webhooks use tenant-owned receipt rows with payload hashes. Exact replay is idempotent, a changed payload under the same event ID is rejected, and older subscription projections cannot replace newer state. `customer.state_changed` validates the Polar customer, product, and benefit identifiers against the configured catalog, then applies the same atomic customer, subscription, and entitlement projection used by reconciliation before it marks the receipt processed. If Polar returns more than one safe subscription, Zara selects the highest safe state and then the newest provider `modified_at` value.

Polar `order.paid` validates the provider `paid` flag, `paid` status, USD currency, integer `total_amount`, invoice number, and provider creation time before storage. It writes one tenant-owned `billing_invoices` row with a stable provider-order key in one transaction. An exact order replay changes nothing. A replay with changed invoice data is rejected. This invoice projection does not enable charge delivery.

Polar `subscription.past_due` is the recoverable payment-failure event. Zara validates the customer, mapped product, `past_due` status, USD amount, and provider times before it writes the monotonic subscription projection. The public billing state changes to `past_due` at once. The durable projection keeps the provider `modified_at` failure time so the approved 72-hour BYO grace rule can be evaluated by the authoritative runtime access posture. Platform-managed PSTN must not use that grace because it creates direct supplier liability.

Checkout registers the tenant for Polar customer-state reconciliation. Reconciliation runs at startup and every 15 minutes, fetches state by the Zara tenant external ID, and atomically applies newer subscription and entitlement projections. A local active subscription or entitlement that is absent from the full provider state becomes revoked. An unchanged pass writes no new repair audit. A repaired state creates a tenant audit entry. Reconciliation does not enable charge delivery.

The only PAYG order projection is the configured `payg-5-usd` credit pack. A paid USD 500-cent order and its 500-cent service-credit grant commit together. Polar `order.refunded` can reverse the pack only when the event reports a full USD 500-cent refund and the full order grant remains unused. The full amount is `refunded_amount` plus `refunded_tax_amount`, because Polar reports the net refund and tax refund separately. Partial refunds are rejected. Repeated paid-order and refund events do not change credit twice. A processing error marks its webhook receipt failed so an exact Polar retry can reopen it.

Approved billing corrections are append-only. One tenant-owned credit or debit adjustment must refer to an existing ledger entry in the same tenant. The approval identity, reason, amount, kind, and time are stored with one correction ledger fact in the same transaction. Exact replay changes nothing. A changed replay or cross-tenant ledger reference fails. ISSUE-246 and ISSUE-247 consume these signed correction facts for budget enforcement and production read models. This operation does not send a provider charge.

Missing catalog, rate, route, or provider duration data creates an explicit incomplete ledger fact. It does not create an estimated or silent zero charge. Browser sandbox V1 usage is explicitly non-billable. Phone tests are separately classified and follow the selected live route rules.

## Telephony Minute Accounting

The telephony service sends a trusted usage fact after it persists a terminal call state. The fact includes the tenant, workspace, call session, provider connection, provider ownership, route, runtime path, commercial mode, outcome, and server-measured duration. Duplicate terminal callbacks use the same ledger idempotency keys.

Platform-managed carrier time rounds connected seconds up to a full minute for each route. BYO routes do not create a platform carrier charge. Standard and premium runtime remain in seconds. Failed calls that never connect create an explicit zero-charge, non-billable fact. Missing provider-connected duration creates an incomplete fact.

## Runtime Cost Accounting

Trusted runtime completion sends measured standard or premium runtime seconds to the same producer. The producer stores the immutable catalog version used for the calculation. It does not round each runtime event to a full minute. PAYG credit consumption and external delivery are later settlement steps.

## Plan Limits And Budgets

`PATCH /organizations/:orgId/billing/budget-policy` lets tenant billing admins configure monthly budget, call-minute, and premium-runtime-minute limits. `POST /organizations/:orgId/billing/budget-checks` evaluates a proposed call or premium runtime reservation against the policy.

Migration `0018_dear_pretty_boy.sql` adds tenant reservation accounts and charge reservations. Migration `0019_curly_ego.sql` adds the expired reservation state. Migration `0020_secret_dreadnoughts.sql` adds finalized usage, session, and time fields with database checks. Migration `0021_ambiguous_trauma.sql` adds the explicit released state and release time. The tenant account row is the database serialization point. A conditional row update can reserve PAYG value only when the new reserved total stays within the current durable credit balance. Concurrent calls cannot both claim the same credit. At the exact expiry time, an abandoned active reservation becomes expired and releases its reserved value once before the next reservation decision. Finalization creates one tenant-qualified PAYG debit, replaces the reserved amount with actual usage, and releases the unused value in one transaction. An exact finalization replay returns the original result without a second debit. A failed-start release returns the full reserved value without a PAYG debit. Its replay changes nothing. A denied reservation returns the remaining local value and does not contact Polar. The rollback is blocked while an active unexpired reservation exists.

The trusted PAYG call-lifecycle service accepts only a server-calculated maximum expected charge. It creates the reservation before it calls the provider-start boundary. If provider start fails, it releases the claim and rethrows the provider error. The catalog-backed reservation quote service calculates this maximum from the server-owned call-duration limit and the effective approved PAYG rates. Runtime charges are prorated by second and rounded up on the total. Platform-managed carrier charges use the route's approved per-minute rate and round the maximum duration up to the next full minute. BYO calls have no platform carrier component. Missing catalogs, rates, routes, route matches, or supported rounding rules stop the quote. Neither service accepts a tenant request price, and neither service has a hardcoded reservation price.

Over-budget behavior is configurable:

- `block`: over-limit checks return `allowed: false` and `action: "block"`.
- `warn`: over-limit checks return `allowed: true` and `action: "warn"`.

Billing state includes `budgetWarnings` when spend, call minutes, or premium runtime minutes cross the configured warning threshold.

Telephony live-route activation, live-call start, and active-call checks read the durable subscription projection and the current budget posture. A `past_due` platform-managed PSTN account cannot activate or start a new call. A `past_due` BYO account can use live runtime only before the exact 72-hour grace end that starts at the provider `modified_at` time. Missing or unknown ownership uses the platform-managed check and fails closed. Inactive subscriptions and hard budget blocks preserve the number setup, credentials, routes, and history, but new inbound calls receive the safe unavailable provider response and a blocked dispatch record. During an active PSTN call, subscription loss uses the existing short call wind-down policy, while a hard budget block closes out after the current turn unless a separate emergency or human policy overrides that behavior.

## Safety

The Polar endpoint uses Standard Webhooks headers and the original signed request body. The API must start with Nest raw-body capture enabled. Customer-state events identify the Zara tenant through `data.external_id`, not the Polar merchant's `data.organization_id`. Invalid signatures and missing raw bodies fail closed when the webhook secret is set. Invalid provider schemas return a safe client error. Local test bypass behavior does not authorize exposing an endpoint without its webhook secret.

Billing APIs require tenant billing admin access for mutations. Public billing responses never return Polar access tokens, webhook secrets, provider bearer tokens, raw provider payload secrets, or decrypted telephony credentials.
